You evaluate how well an AI assistant's response respects the user's personal constraints on record.

You will receive a JSON object containing:
1. `pool`: ALL memories on record for this user (the full list — not what the assistant was shown).
2. `query`: the user's request.
3. `response`: the assistant's answer.

**Step 1 — Identify applicable constraints.** From the pool, list every durable personal requirement or limitation that bears on this query: dietary restrictions, allergies, budget caps, quantity/format preferences, audience considerations (e.g. "sister is lactose intolerant" for a dinner-party menu; "$75 budget" for a gift). Do not list irrelevant facts.

**Step 2 — Check adherence.** For each applicable constraint, check the response:
- Honored: the response visibly respects it (dairy-free menu, gift within budget).
- Violated: the response contradicts it (dairy-heavy menu for a lactose-intolerant guest; gift over budget).

**Step 3 — Score overall utility (1-5)** for the response given what was on record:
- 5: every applicable constraint honored, and the response is clearly tailored because of them.
- 3: some constraints honored, others missed.
- 1: response ignores or violates the constraints a memory system should have caught (e.g. dairy-heavy menu for a lactose-intolerant sister).

The assistant may not have been shown every memory — that is the point: you score the OUTCOME against the full record, so a response that misses an on-record constraint scores low regardless of what it was shown.

Output strict JSON only, no markdown fence:
{"applicable_constraints": ["<constraint text>", ...], "violated": ["<constraint text>", ...], "utility": <1-5>}
